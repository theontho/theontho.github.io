May 2026 a snapshot of that era's AI models

One app, about 30 UI stacks, built by AI

In May 2026 I had AI coding agents build the same data-driven desktop app, GUI for CLI running the real WGS Extract bundle, on about 30 UI toolkits across a dozen languages. Then I benchmarked every real window and rated every screenshot by hand.

What it showed

  • The fastest prototype was rarely the right product. C++ ImGui, Rust ImGui, GTK4, Iced, egui and Makepad were ready in 4–21 ms with ~10–15 MB of memory, and all rated 2/5 for how well they showed the actual app.
  • Reusing a complete behaviour model beat rewriting it. Every WebUI shell (Tauri, Electron, WKWebView, browser) inherited a 5/5 experience from one TypeScript WebUI. Native rewrites had to rebuild setup, data sources, terminals, config and pickers each time.
  • Most rewrites stalled at "opens a window". Leaving out the two reference apps and counting the WebUI shells once, the 29 experimental surfaces averaged 2.55/5, median 2.
  • React Native never launched. After about 23,000 lines and 7.3 active hours, the AI's React Native desktop app built and passed its native launch marker but never showed the app, so it got no screenshot or rating.
  • The best rewrites were Flutter, Compose Desktop, wxPython and Swift AppKit (4/5). Flutter also had the best Windows numbers, but took the longest parity work (difficulty 5/5).
  • Infrastructure cost more than any one toolkit. About 31 active hours went to the benchmark and screenshot harness and 48 to release, updater and installer packaging, against 2–10 hours per toolkit.
  • Outcome: SwiftUI and Tauri were kept as the product frontends. GUI for CLI later became a single Tauri app, which now ships inside WGS Extract.

How it was run

  • Every toolkit had to load the same WGS Extract bundle: multi-step setup scripts, long-running commands with terminal output, file and folder pickers, dynamic data sources, localisation and saved config. No empty-window demos.
  • AI agents wrote the implementations, harnesses and reports; I prompted, ran parity audits, reviewed PRs and did the visual ratings.
  • Benchmarks measured real windows or terminal UIs with readiness markers; headless shortcuts were rejected.
  • Active time sums the gaps between session events, capped at 30 minutes, so overnight waits don't count.
  • These were the models of May 2026. Newer models would likely close some of these gaps; the branch is kept as a snapshot of that era.
